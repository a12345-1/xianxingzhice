## 一、已实现功能

### 1.1 P1 需求输入（首页）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 一句话自然语言输入 | 多行输入，占位符「周末两天放松一下，别太赶」 |
| 2 | 目的地选择 | 8 个城市的标签，点选即生效 |
| 3 | 出发日期 | 日期控件，最早只能选今天；留空则取下个周六 |
| 4 | 人数 | 步进器 1—10，未填显示「—」 |
| 5 | 天数 | 步进器 1—15，未填显示「—」，不预置默认值 |
| 6 | 预算上限 | 数字输入 + 「不限」快捷 |
| 7 | 智能识别 | 一键读这段文字，自动回填城市 / 日期 / 人数 / 天数 / 预算 |
| 8 | 缺信息反问 | 缺什么问什么，用「请问……？」口吻，并把对应控件标红 |
| 9 | 信息齐全自动收起 | 四项齐了就不再显示「智能识别」按钮 |

| 11 | 最近行程 | 最多 3 条，**含未保存草稿**；可删除、可展开消费明细 |
| 12 | 提交校验 | 文字 ≥4 字、天数 1—15、预算为空或 ≥100 |
| 13 | AI 状态角标 | 显示「AI 已连接 · deepseek-chat」或「规则模式」 |

## 二、暂时的让步（先说清楚的简化）

| # | 项目 | 现在的做法（以及为什么这么定） | 影响 |
|---|---|---|---|
| 1 | 天气 | 8 个天气模板，按「城市 + 日期 + 天序号」确定性随机抽取。真接口对 15 天以后无数据，答辩还要解释预报误差 | 已标注 `source=template`，不能当真实预报 |
| 2 | 交通费 | 按距离估算：打车 13 元起 + 2.6 元/公里，公交 2 元/人。实时打车价要接高德路径规划，每段一次请求 | 与真实价格有偏差，属估算 |

| 4 | POI 数据 | 8 城共 119 条（景点 47 / 餐饮 48 / 住宿 24），人力整理 + 高德校验 | 4 天以上会出现无点位可排，页面会明说数据不足 |
| 5 | 门票 / 住宿价 | 门票多为 0 或参考价，住宿为参考价位，无实时票价源 | 预算页已注明以实际为准 |

| 7 | 模型编排 | 单模型（DeepSeek）+ 代码编排，没有 Dify 环境 | 架构图里的 Dify 编排属「后续演进」 |

## 四、问题与修改记录

### 4.1 需求解析类

| 问题 | 原因 | 修改 |
|---|---|---|
| 「5 天 4 晚」被识别成 3 天 | 界面天数默认 3，生成时无条件用控件值；「4 晚」根本没解析 | 文本写明天数时以文本为准（用户手动改过控件才以控件为准）；新增 `晚+1`、中文数字、`3日游` 解析 |
| 「预算三千」识别不到 | 只认阿拉伯数字 | 支持 三千 / 八百 / 1.5k / 3000 块 |
| 「我和一个朋友」算成 1 人 | 只匹配 `N 人` | 支持 我和X / 我们三个 / 一家三口 |
| 「去霍格沃茨」编了个长沙行程 | 解析不到城市时静默降级到长沙 | 改为报 `UNKNOWN_CITY` 并给出 8 个可选城市 |
| 「我想出去玩」直接生成 | 没有缺信息检测 | 加 `/api/chat` 反问，缺什么问什么 |

### 4.2 路线规划类

| 问题 | 原因 | 修改 |
|---|---|---|
| 不同城市生成同样的行程 | 无数据时静默回落长沙 | 改为 `NO_DATA` 报错，并补齐 8 城数据 |
| 同一景点重复出现 2—3 次 | 曾经让模型直接排行程，模型不管「用过的点」 | 改为「模型只挑点 + 代码去重」，全城去重 |
| 两顿饭排在一起（15:30 一顿、17:00 一顿） | 景点排完再追加餐饮；夜市被当午饭 | 改为按时间窗排：上午景点 → 午饭 11:45 → 下午景点 → 晚饭 18:00 → 住宿；餐厅必须在该时段营业 |
| 住宿离最后一个点 40—80 公里 | 模型按名字选，不看距离 | 超过 15 公里自动换成最近的一家 |
| 相邻两点 20 公里来回跑 | 无距离约束 | 超过 15 公里换成更近的点，换不到就删 |
| 5 天行程直接崩（IndexError） | 候选点排空后仍取 `picks[0]` | 空白天改为「这天没有可安排的地点」 |
| 住宿永远排最后，↑↓ 点了没反应 | 后端把住宿强制锁在末位 | 去掉硬锁；到边界按钮置灰并提示 |

### 4.3 预算与价格类

| 问题 | 原因 | 修改 |
|---|---|---|
| 预算占比条看起来是固定宽度 | 用的是「总花费 ÷ 总预算」，且在“当天预算”卡里 | 改四色堆叠条按当天实际比例分段，每行加百分比 |
| 四类明细加起来 ≠ 总额 | 明细用数据库单价求和，总额用折后价 | 明细改为从排好的条目汇总，恒等于总额 |
| 2 人 / 5 人行程价格不变 | 所有价格都按单人算 | 门票餐饮 × 人数，住宿 × 房间数，打车 × 车数，公交地铁 × 人数 |
| 降住宿档次来回横跳 | 候选包含当前酒店，来回换 | 只允许换更便宜的，换不到就停 |
| 交通费一直是 0 | 只算了时间没算钱 | 加打车 / 公交估算并计入交通分类 |
| 改单价后总额不变 | 只能改时长 | 条目展开加单价输入，改完即时重算 |

### 4.4 交互与前端类

| 问题 | 原因 | 修改 |
|---|---|---|
| 手机长按拖拽几乎拖不动（尤其往上） | 长按期间页面先被滚动接管，之后收不到移动事件 | 改为 ⠿ 手柄触发，手柄上 `touch-action:none`，拖动事件挂 document |
| 生成报 422 | Pydantic v2 里 `int = None` 拒绝显式 null | 改成 `int \| None`，并加中文 400 错误处理 |
| 时间改不了 | 只读展示 | 展开加时间输入，改完后续条目顺延 |
| 缺信息只弹提示，不知道填哪 | 提示文字与表单分离 | 反问卡 + 对应控件标红高亮 |
| 智能识别按钮一直显示 | 没判断信息是否已齐 | 四项齐了自动收起 |

### 4.5 数据与环境类

| 问题 | 原因 | 修改 |
|---|---|---|
| 重启后高德抓的数据被覆盖 | 用行数判断是否需要重新灌种子 | 改为 CSV 内容哈希比对 |
| 高德搜出「白鸟村文化小广场」这类噪声 | 只按类型码查询 | 改为关键词查询 + 评分 ≥4.2 + 噪声词过滤 |
| 火锅店被当成景点调整时间 | 自动调整没区分类型 | 只处理 `attraction` |
| 重新部署后历史行程清空 | Render 免费版无持久磁盘 | 已在文档中说明；计划加「预置示例行程」 |
