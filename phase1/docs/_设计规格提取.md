# 设计规格提取（P1–P5 · v1/v2 · 单人模式）

> 来源：`design/布局与断点.md`、`design/flows/主流程.md`、`design/pages/*.md`、`docs/接口数据字段说明.md`。文案、字段名、数值均原文照抄；文档没写的标「文档未定义」，不推测。

# P1 首页需求输入
## 字段清单

| 字段 | 类型 | 必填 | 显示/校验规则 |
|---|---|---|---|
| `raw_text` | string | 是 | 自然语言需求，**4–200 字**；占位符给例子，不写「请输入」；手机 6 行高、电脑最大宽 720 |
| `day_count` | int | 是 | 默认 `3`；范围 **1–15**；「数字步进器，不做下拉」；手机步进器 44×44 触控 |
| `budget_limit` | int | 否 | 默认「不限」；「留空或 0 = 不限，此时预算页只汇总不判超支」；手机数字键盘，右侧「不限」快捷 |
| `destination` | string | 否 | 「不从控件收，由后端从 `raw_text` 抽；抽到后以 chip 回显在输入框下方」，灰色小字、不可点 |
| `people` | int | 否 | 「同上，从文本抽。抽不到按 1 人算，不单独问」；回显格式 `杭州 · 2 人` |
| `submit_state` | 前端内部，不提交 | — | `idle` / `submitting` / `error`，「控制按钮文案与禁用」 |
| `error_msg` | 前端内部，不提交 | — | 「校验或请求失败的人话原因，显示在按钮下方一行」 |

- 占位符原文 `周末两天放松一下，别太赶`；电脑左栏 3 条可点示例 `· 周末两天，带娃，别太累`、`· 五天四晚，成都，吃货路线`、`· 十一，情侣，预算 5000`（点了直接填进输入框）；预算留空时「占位符显示「不限」，不要把 0 显示出来」。
- 主按钮 `生成我的行程`（手机 300×48）；手机首屏标题 `想去哪儿，玩几天？`；电脑标题 `一句话，排好一趟旅行` + 副文案 `说清想去哪、几天、花多少，剩下的交给它。`；品牌名 `闲行智策`，右上 `[我的]`（手机）/ `我的行程` `帮助`（电脑）。底部 `最近行程` 条目原文：手机 `杭州 3 日 · 11-12 生成 ›`、电脑 `杭州 3 日 · 11-12 生成 · 2860 元 ›`；「最多 3 条，没有则整块隐藏」。

## 交互规则
1. 「**输入框自动聚焦，但手机端不自动弹键盘**（弹了会挡住按钮，用户第一眼看不到「生成」）。」
2. 「回车是换行，不是提交。提交只有主按钮一个入口。」
3. 「解析回显（`杭州 · 2 人`）在停止输入 600ms 后出现，用户手动改过 `day_count` 就不再被覆盖。」
4. 「天数步进器范围 1–15，到边界时按钮置灰，不弹提示。」
5. 「预算留空按「不限」处理，占位符显示「不限」，不要把 0 显示出来。」
6. 「提交后按钮变「正在规划…」并禁用，防止重复提交；**不回显空状态**，直接进生成中。」
7. 「底部「最近行程」只取本地库最新 3 条，点击直接进 P2（只读浏览）或 P5。」
8. 生成中＝「同一路由，仅替换内容」的过渡态，不占页面编号；「显示步骤进度，可中断」，只读 `meta.agents`。
9. 校验时机：**提交时按顺序**校验（下表），「三条都不通过时才一次性全标红；只错一条就只标一条。」

| 顺序 | 检查 | 不通过的表现（原文） |
|---|---|---|
| 1 | `raw_text` 去空格后 ≥ 4 字 | 输入框描边变红，下方提示「多说一句，比如想去哪、玩几天」 |
| 2 | `day_count` 在 1–15 | 步进器变红，提示「天数填 1–15 天」 |
| 3 | `budget_limit` 为空或 ≥ 100 | 提示「预算至少 100 元，或选不限」 |

- 主流程口径：输入不足 4 字 / 天数越界 / 预算 < 100 →「P1 就地标红，其它输入保留」，禁止「弹窗报错、清空输入」；「超时 30 秒按失败处理」。

## 三种状态
- 空态（首次使用）：「`最近行程` 整块隐藏；输入框占位符换成引导示例，不留白」
- 正常态：「如上图，`最近行程` 有数据则显示」
- 加载态：按钮变「正在规划…」并禁用，显示智能体步骤进度，可中断
- 错误态：「请求失败不离开本页，按钮下方一行红字「没生成出来，再试一次」，**所有输入保留**」

## 跳转
- P1 →生成成功→ P2 行程浏览（带 `trip_id`）；「浏览器返回到 P1，输入内容保留」
- P1 →生成失败→ 留 P1 显示错误；「输入全保留，按钮可再点」
- P1 →点最近行程→ P2（只读）或 P5 列表；→点「我的」→ P5 已保存行程

## 双端差异（手机 vs 电脑）
- 结构：手机单栏竖排 ｜ 电脑两栏（左文案与示例 / 右表单），内容区最大宽 1280 居中，左右 **5:7**，间距 **48**
- 示例：手机只做输入框占位符 ｜ 电脑左栏 3 条可点示例，点了直接填进输入框
- 输入框：手机全宽 ｜ 电脑最大宽 720，「**不铺满**」
- 天数/预算：手机各占一行纵向堆叠 ｜ 电脑行内标签与控件同一行
- 最近行程：手机竖排最多 3 条 ｜ 电脑同左，多显示总花费；键盘：手机预算用数字键盘、弹起时页面上推 ｜ 电脑无此问题
- 硬规则：「业务逻辑两端完全一致，不因屏宽改变校验规则。」

# P2 行程浏览与编辑
## 字段清单
行程级（必填：文档未定义）：

| 字段 | 类型 | 显示/校验规则 |
|---|---|---|
| `trip_id` | string | 行程唯一标识，后续所有请求都带 |
| `title` | string | 如「杭州 3 日」，标题栏显示 |
| `start_date` / `end_date` | date | 概要条显示 `05-01 起 · 3 天`，格式 `YYYY-MM-DD` |
| `people` | int | 人数，参与人均计算 |
| `total_cost` | int | 全部天合计（元）；界面 `2860/3000`，超支时数字变红 |
| `budget_limit` | int \| null | `null` = 不限，不判超支 |
| `status` | enum | `draft` 初稿 / `edited` 改过 / `saving` / `saved` |

天级（必填：文档未定义）：

| 字段 | 类型 | 显示/校验规则 |
|---|---|---|
| `day_index` | int | 1 起，天 Tab 与左栏列表用 |
| `date` / `weekday` | date / string | 如 `05-01` / `周六`；头行 `周六 · 多云 16~24° · 今日 320` |
| `weather` | object \| null | `condition` / `temp_low` / `temp_high` / `rain_prob` / `source`；「拿不到时整块不显示」 |
| `day_cost` | int | 当天合计，随编辑实时变；`= items[].cost 之和` |
| `walk_level` | enum \| null | `light` / `medium` / `heavy`；界面 `体力：中等` |

条目级（卡片上的东西）：

| 字段 | 类型 | 必填 | 显示/校验规则 |
|---|---|---|---|
| `item_id` | string | 是 | 全局唯一，编辑时按它定位 |
| `seq` | int | 是 | 当天顺序，从 1 连续；拖拽后重排 |
| `type` | enum | 是 | `spot` 景点 / `food` 餐饮 / `hotel` 住宿 / `transport` 交通 / `rest` 休息 |
| `name` | string | 是 | 地点名 |
| `start_time` / `end_time` | `HH:mm` | 是 | 24 小时制，时间轴定位；界面 `09:00`、`2h` |
| `duration_min` | int | 是 | 时长（分钟） |
| `transport` | object | 是 | `mode`（`walk`/`bus`/`taxi`/`train`）、`from_prev_min`（距上一项耗时，首项 0） |
| `cost` | int | 是 | 该条费用合计；「应等于 `cost_breakdown` 四项之和」 |
| `cost_breakdown` | object | 是 | `ticket`/`food`/`transport`/`hotel`，全整数，用于预算四类归集 |
| `source` | enum | 是 | `knowledge_base` / `model` / `user`，**界面上须可区分**，推测值要标 |
| `warnings` | array | 是 | 元素 `{code, message}`，如 `[{code:"CLOSED_DAY", message:"周一闭馆"}]`；无则 `[]` |
| `open_hours` | string \| null | 否 | `07:00-18:00` / `全天`；「有则参与校验，无则标「待核实」」 |
| `closed_days` | array\<int\> | 否 | 闭馆星期，0 = 周日、1 = 周一 … 6 = 周六 |

前端编辑态（不提交）：

| 字段 | 说明 |
|---|---|
| `dirty` | 是否有未保存改动，控制离开确认 |
| `editing_item_id` | 当前展开编辑的条目 |
| `drag_item_id` | 拖拽中的条目 |

- 来源标注（右下角小字）：「`knowledge_base` 不标，`model` 标「推测」，`user` 标「已改」」；卡片文案示例 `西湖 · 断桥　景点` / `步行 · 免费 · 预置库` / `灵隐寺　景点 ⚠ 闭馆` / `门票 45 · 打车 20 分`；加条目按钮 `＋ 加一个地点`；电脑候选地点行 `· 河坊街　步行 8 分`。

## 交互规则
1. 「**浏览与编辑不分页**：点条目即展开编辑，展开态只允许一个，点另一条自动收起。」
2. 「**草稿态**：任一改动置 `dirty=true`，顶栏出现「编辑中」；返回或关闭需二次确认「有未保存的改动，放弃？」。」
3. 「**保存只提交差异**：前端记录改了哪几条（增/删/改/序），按条目维度提交，不整单回传。」
4. 「**改一条，钱立刻变**：本地先算增量改浮条数字，随后以服务端返回为准覆盖（避免算错）。」
5. 「**拖拽改顺序 = 重排时间**：按「上一项结束 + 交通耗时」重算，原时间不保留。」
6. 「**手改时间后默认顺延后续项**，可关闭；关闭时只校验当前条。」
7. 「**冲突允许保存**，只在卡片上留警示。」
8. 「**删除与替换都有 3 秒撤销**，超时落盘。」手机顶部 3 秒提示条 / 电脑右下角 toast。
9. 「每次改动 300ms 防抖后触发校验，键盘输入不逐字符请求。」
10. 排序：手机「长按 0.5s 激活拖拽，激活后锁滚动」＋触感反馈；电脑「拖 `⠿` 手柄，或 `↑`/`↓` 键」。点开卡片后的行内操作原文 `[换一个] [调时长] [删除]`；电脑 hover 出 `⋯` 再点开菜单。
11. 保存后「留在本页，浮条显示「已保存 · 查看我的行程」」。

时间校验查什么：

| 检查项 | 判定 | 提示（原文） |
|---|---|---|
| 闭馆日 | 当天星期落在闭馆日 | 「⚠ 周一闭馆」 |
| 开放时段 | 到达早于开门 / 晚于停止入场 | 「8:30 才开门，你 8:00 到」 |
| 午休 | 落在午休区间 | 「12:00–13:30 午休」 |
| 路程耗时 | 与上一项间隔 < 交通耗时 | 「需 40 分钟车程，只留了 15 分钟」 |
| 顺序倒挂 | 先去的店开门更晚 | 「先去的这家 10 点才开」 |

- 「查不到数据的项标「待核实」：不报通过，也不当错误。」

## 三种状态
- 正常态：「如上图；无冲突时不显示校验块，避免噪音」
- 空态：「某天没有条目：「这天还空着，加一个？」+ 3 个附近推荐；整天缺失时也给这一天留 Tab」
- 加载态：保存时 `status: saving` → `saved`
- 错误态：「校验服务不可用：灰条「暂时无法校验开放时间，请自行确认」，浏览与保存照常，状态栏不显示「已校验」」
- 保存失败：「保持 `dirty`，提示「保存失败，再试一次」，数据不丢」，「不允许清空编辑状态」

## 跳转
- P1 →生成成功→ P2（带 `trip_id`）
- P2 →浮条「预算」/ 右栏预算→ P3；回 P2「保留原天与滚动位置」
- P2 →「贴士」→ P4；回 P2「保留原天」
- P2 →「保存」→ 留本页，浮条「已保存 · 查看我的行程」→ P5
- P2 →「返回」且 `dirty`→ 二次确认；确认丢弃回 P1，取消留 P2
- P5 →打开历史行程→ P2（P2 文档写「只读，点条目不展开编辑」；P5 文档写「不做只读模式」，冲突待裁决）

## 双端差异（手机 vs 电脑）
- 换天：手机顶部 Tab + 左右滑 ｜ 电脑左栏竖列表（240 固定，当前天高亮），跟滚动固定
- 预算：手机底部常驻浮条，点「预算」进 P3 ｜ 电脑右栏卡片（320 固定 · sticky），分类明细直接露出
- 时间校验：手机卡片上警示标 + 点开看原因 ｜ 电脑右栏独立一块逐条列出
- 候选地点：手机点「换一个」拉起底部抽屉 ｜ 电脑右栏常驻列表，点一下即替换
- 排序：手机长按 0.5 秒激活拖拽、触感反馈 ｜ 电脑拖 `⠿` 手柄或选中后 `↑`/`↓`
- 条目操作：手机展开后常驻「换一个 / 删除」 ｜ 电脑 hover 出现 `⋯`
- 保存 / 删错撤销：手机顶部「保存」、顶部 3 秒提示条 ｜ 电脑顶部「保存」+ 状态栏「编辑中」、右下角 toast
- 主区：手机单栏卡片流 ｜ 电脑主区 flex、最大 720，顶栏多 `[分享]` `[⋯]`
- 手机底部浮条原文 `今日 320 · 合计 2860/3000` + `[预算] [贴士] [编辑]`，「常驻不下沉」。

# P3 预算清单
## 字段清单

| 字段 | 类型 | 显示/校验规则 |
|---|---|---|
| `budget_limit` | int \| null | 预算上限；`null` 表示「不限」，此时不判超支，只汇总 |
| `total` | int | 已用合计（元），`= 四类 amount 之和`；大数字展示 `2860 / 3000` |
| `remaining` | int | 剩余 = `limit − total`，可能为负 |
| `over_budget` | bool | 是否超支；`limit` 为 `null` 时恒 `false` |
| `over_amount` | int | 超支金额（`total − limit`，「未超时为 0」） |
| `per_person` | int | 人均 = `total / people`，**向下取整**；界面 `人均 1430 · 2 人` |
| `categories` | array | 「固定四类，顺序固定」：`ticket` `transport` `food` `hotel` |
| `suggestions` | array | 省钱建议；无建议给空数组 |

`categories[]` 单项：

| 字段 | 类型 | 显示/校验规则 |
|---|---|---|
| `key` | enum | `ticket` / `transport` / `food` / `hotel`，「固定四类不加不减」 |
| `label` | string | 门票 / 交通 / 餐饮 / 住宿（顺序固定） |
| `amount` | int | 该类已用金额 |
| `ratio` | float | 占 `total` 比例，0–1，**保留三位小数**；`total` 为 0 时给 0；界面 `16.8%` |
| `over` | bool | 该类是否高于「参考占比」；「只做标黄提示，不参与超支判定」 |
| `items` | array | 明细 `{name, cost, day_index}`，点开展示；行格式 `D2 · 灵隐寺 · 45 元` |

`suggestions[]`：

| 字段 | 类型 | 显示/校验规则 |
|---|---|---|
| `code` | string | 建议类型，如 `SWAP_SPOT` / `CUT_FOOD` |
| `message` | string | 人话，如「雷峰塔换免费观景点，省 40 元」 |
| `save_amount` | int | 预计可省金额；界面 `省 40 元` |
| `target` | object | 关联条目 `{day_index, item_id}`，点击直达 P2 对应位置 |

- 超支条原文：手机 `⚠ 已超支 160 元`（「超支才出现，红底白字，常驻」）；电脑 `⚠ 已超支 160 元，主要超在「餐饮」——点建议可直达对应条目`。
- 标题：手机 `‹ 返回　预算`；电脑 `‹ 返回　预算 · 杭州 3 日 · 2 人` + `[返回行程] [保存]`；区块标题 `分类明细`、`省钱建议`；进度条示例 `████████████████░░░　95%`。

## 交互规则
1. 「**四类固定**：门票 / 交通 / 餐饮 / 住宿。用户不关心「其他」，多出来的小额统一并入其所属类别，实在无法归类才进「门票」之外的最近类。」
2. 「**超支判定只比 `total` 与 `limit`**；单类是否「超」是相对参考占比（**门票 20% / 交通 20% / 餐饮 35% / 住宿 25%**），只做标黄提示，不参与超支判定。」
3. 「`budget_limit` 为 null 时：不显示超支条与百分比，进度条改为「已用 2860 元」，分类占比按 `total` 算。」
4. 「点分类行 → 展开该类明细（`items`），每条显示「D2 · 灵隐寺 · 45 元」，可点进 P2 定位。」
5. 「点建议 → 回 P2 并滚动到 `target` 条目，条目高亮 **2 秒**。」
6. 「本页数据**只读**。所有修改都在 P2，避免两处都能改导致状态不同步。」
7. 「「保存」在本页也可用（当从 P2 进来时），保存后按钮变「已保存」。」进度条「按已用/上限画条」。

## 三种状态
- 正常态：「未超支：进度条绿色，无顶部条；超支：进度条红 + 顶部红条 + 差额」
- 空态：「行程没有任何条目：显示「还没有花费，回行程加几个地点」，按钮回 P2」
- 加载态：文档未定义
- 错误态：「建议接口失败：只隐藏「省钱建议」整块，不显示错误；分类与总数照常（本地可算）」

## 跳转
- P2 →浮条「预算」/ 右栏预算卡→ P3
- P3 →分类明细里的条目→ P2 并定位到该条目（高亮 2 秒）
- P3 →点建议→ P2 并高亮目标条目；→返回→ P2（停留原天）

## 双端差异（手机 vs 电脑）
- 结构：手机单栏竖排（总数 → 分类 → 建议）｜ 电脑左总数卡（420 固定，sticky）+ 右分类表与建议

# 全局约定
## 断点、栅格、内容区宽度

| 名称 | 宽度 | 布局 | 设计要求 |
|---|---|---|---|
| `sm` | ≤ 767 | 单栏 | 完整稿，**375 × 812** 为基准 |
| `md` | 768 – 1023 | 双栏 | 不单独出稿，跟随 `sm` 单栏结构，仅内容区变宽 |
| `lg` | 1024 – 1439 | 双栏 | 出稿（可复用 `xl` 稿的双栏裁切说明） |
| `xl` | ≥ 1440 | 三栏 | 完整稿，**1440 × 900** 为基准 |

- 「用 `min-width` 向上叠加，不在 767/768 之间留空档。」「**1440 是设计基准，不是最大宽**：内容区最大 1280 居中，两侧留白随视口增长。」
- 栅格：「12 列，列间距 24，内容区最大宽 1280。」页边距：「`sm` 16、`lg` 32、`xl` 自动居中（两侧 ≥ 80）。」「卡片圆角 12，卡片内边距 `sm` 16 / `lg` 24。」单页固定宽度：P2 左栏 240 / 右栏 320；P3 左卡 420；P5 左列表 420；P1 两栏 5:7、间距 48。

## 手机端固定元素 ↔ 电脑端对应物（硬约定，改前先商量）

| 组件 | 手机（sm） | 电脑（xl） | 备注 |
|---|---|---|---|
| 天切换 | 顶部 Tab + 左右滑 | 左侧固定列表，当前天高亮 | 电脑端不与页面一起滚动 |
| 预算汇总 | 底部常驻浮条 | 右侧栏独立卡片，随滚动停留 | 超支变红两端一致 |
| 贴士入口 | 浮条上的「贴士」按钮 | 右侧栏卡片，直接露出前 2 条 | 电脑端信息密度更高 |
| 编辑 / 分享 | 浮条按钮 | 顶部工具栏 + 卡片 hover 出操作 | **hover 操作在手机端必须常驻可见** |
| 输入框 | 全宽，6 行高 | 居中卡片，最大宽 720 | 电脑端不铺满屏宽 |
| 抽屉 / 弹层 | 底部抽屉 | 右侧面板或居中 modal | 同一内容两种容器 |
| 条目排序 | 长按 0.5s 激活拖拽，激活后锁滚动 | 拖 `⠿` 手柄，或 `↑`/`↓` 键 | 手机端必须解决「拖拽与滚动打架」 |

## 硬性规则（原文引用）
1. 「**不能只有 hover**：手机没有 hover，任何靠鼠标悬停才出现的操作，在 `sm` 必须常驻或有明确入口。」
2. 「**不能只在电脑端有**：电脑端多出来的信息块（比如右侧贴士前两条），手机端必须在某一屏能点到，不能因为放不下就砍掉功能。」
3. 「同一功能两端形态可以不同，但**信息不能少**。」
4. 「`null` 不显示 `null`」：为 `null` 时显示「—」，可交互元素直接隐藏。「金额不换算」：整数元，不做单位换算、不加「约」字。「时间不重算」：直接用 `start_time`/`end_time`，前端只在拖拽排序时按 `transport.from_prev_min` 本地预演，落盘以服务端为准。
5. 「`source=model` **必须可见**」：卡片或行列上标「推测」，防误导的硬要求。「`warnings` 非空即有警示」：不区分严重级别，全部同等提示。
6. 「`days` 长度必须等于 `day_count`」：不等视为 `partial`，缺的那天渲染空态而不是报错；`items` 允许空数组，**不允许为 `null`**。
7. PATCH「都必须回完整的 `budget` 与更新后的 `item`」，前端**以服务端返回为准**，「不信任前端算的钱」。
8. 输入不足 4 字 / 天数越界 / 预算 < 100：**不允许**「弹窗报错、清空输入」；生成失败**不允许**「无声转圈、自动无限重试」；天气不可用**不允许**「用模型猜测的天气顶替」；开放时间缺失**不允许**「编造开放时间」。
9. 「**宁可少显示，也不要编数据。** 凡是模型推测的，`source` 必须如实标 `model`。」`message` 「必须是**给用户看的中文**，不要塞错误码或英文堆栈」。
10. 本期明确不做：结伴模式、分享只读链接、账号与云同步、跨天移动条目、加一天/减一天；编号 P1–P5 是稳定标识，「结伴相关页面已全部移除，不要加回来」。
