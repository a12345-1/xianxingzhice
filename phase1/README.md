## 模型接入（方案 C：模型做语言，代码做账）

`.env` 里填 `LLM_API_KEY` 就启用，不填自动退回本地规则（`MOCK_MODE=auto`）。

| 环节 | 谁做 | 说明 |
|---|---|---|
| 需求解析 | **模型** | 懂“预算别超过八百”“不想太赶”这类自然语言 |
| 行程生成 / 排程 | **代码** | 选区、排时间、控预算，结果可复现 |
| 时间校验 / 自动调整 | **代码** | 闭馆、营业时间、顺延与替换 |
| 预算核算 | **代码** | 算术不交给模型 |
| 贴士文案 | **模型**（基于事实） | 只润色，不许编造天气/价格 |
| 一句话改行程 | **模型理解 + 代码执行** | 模型只输出动作 JSON，增删改由代码做 |

实测：一次完整生成约 **4—6 秒**（2 次模型调用），失败自动降级到规则。

### 一句话改行程

```powershell
curl -X POST http://127.0.0.1:8002/api/trips/<id>/command ^
  -H "Content-Type: application/json" ^
  -d "{\"text\":\"把第二天下午的行程删掉\"}"
```

返回完整行程 + `command: {ok, action, message}`。
支持 action：`replace` / `delete` / `move` / `insert`，找不到目标就返回 `info` 并说明原因，不会瞎改。

```powershell

```

脚本会：按景点名在高德查坐标（名字对不上时用 `ALIAS`/`MANUAL` 兜底）→ 合并 CSV 的门票与备注 →

## 联网补充城市数据（高德）

配置 `AMAP_KEY` 后，首页多一个「联网获取该城市地点」按钮：

```
用户输入“去杭州两天” → 识别城市=杭州 → 调高德 POI 搜索（景点/餐饮/住宿）
→ 写入 poi 表（source=amap，附 fetched_at）→ 排程照旧走本地确定性逻辑
```

- 接口：`POST /api/cities/{city}/refresh` → `{city, imported, source}`
- 没配 Key：返回 `NO_AMAP_KEY`，前端直接提示，不影响原有示例数据
- 高德失败：返回 `AMAP_FAILED`（超时/配额/Key 无效），前端显示原因
- 高德没数据：返回 `NO_RESULT`

**搜索策略**（重要）：只用分类编码会拉回“村口小广场”，所以按关键词搜 + 评分过滤：

| 类型 | 关键词 | 过滤 |
|---|---|---|
| 景点 | 景区 / 博物馆 / 步行街 / 公园 | 评分 ≥ 4.2，去掉停车场/地铁站/售票处等，按评分取前 14 |
| 餐饮 | 美食街 / 小吃 | 同上，取前 8 |
| 住宿 | 酒店 | 同上，取前 4 |

> 高德的 `opentime` 字段经常为空，这种情况统一按「全天」处理，需要在详情页人工核实。
> 免费配额以高德控制台为准，课程演示足够。
